# learn-atlas：把知识种进图谱

你的任务不是复述整段回答，而是判断：**这轮对话里有没有值得几个月后重新看的东西？** 有，就把它压缩成几条准确的结论，合并进知识库；没有，就什么都不做。

## 何时使用

- 上下文出现 `【learn-atlas 学习模式】`：在正常回答结束后执行本流程。
- 上下文出现 `【learn-atlas 历史归档扫描】`：回顾当前会话，把已经讨论过但尚未入库的知识补录进去。这不是新的提问，不要重新回答历史问题。
- 用户明确说“记下来 / 写入知识库 / 存到学习图谱”：执行本流程。
- 其他情况不要主动写入。

## 先判断值不值得写

值得写：

- 定义，以及它**如何运行**：调用链、数据流、状态变化、关键步骤
- 参数如何改变结果，公式、数量级、因果关系
- 权衡、适用边界、失败模式、常见误区
- 可复用的工程实践、设计原则、排查思路
- 用户纠正了之前的理解，形成了更准确的结论

不要写：

- 寒暄、追问、情绪表达、对答案的评价
- 一次性的命令输出、临时排错过程、工具报错
- 有时效性的新闻、价格、版本号（除非是知识本身的一部分）
- 不确定的猜测；宁可少写，不要写错
- 密钥、token、密码、内部地址、公司内部数据、个人隐私
- 只对当前私有代码库有意义的细节

如果这轮只是澄清、举例或换个说法，没有新增结论，直接跳过，不要调用脚本。

### 核心内容自检

写入前问自己：

1. 读者只看这条笔记，能否复述它**怎么工作**，而不只是知道它“是什么”？
2. 有没有写清输入、关键步骤、输出，以及参数如何改变结果？
3. 有没有边界条件、失败模式或取舍？
4. 有没有把对话里的具体解释压缩成可迁移的机制，而不是一句泛泛的说明？

如果只能写出“是什么”，要么继续从本轮回答里提炼机制，要么只记录确定的核心结论，不要用空话凑数。

## 历史归档扫描

用户只输入 `/learn`（不带主题）时，会触发一次历史归档扫描：

- 不要重新回答历史问题，也不要输出“我整理了哪些内容”的清单。
- 按主题把会话中的结论分组；同一主题只合并到一个页面。
- 每个不同主题先 `search` 再 `add`，最多处理 5 个主题。
- 之前已经记录过的结论不要重复写；没有新内容就只回复一句“当前会话没有需要新增的知识。”
- 仍要过滤敏感信息、临时排错和不确定的猜测。

## 工作流

### 1. 先搜索，避免重复建页

```bash
python3 "$HOME/.config/opencode/skills/learn/scripts/learn.py" search "logits softmax"
```

- 有高度相关的页面 → 合并进该页，复用它的 `category` 和 `slug`。
- 只是相关但不是同一主题 → 新建页面。
- 不确定目录时先看树：

```bash
python3 "$HOME/.config/opencode/skills/learn/scripts/learn.py" tree
```

路径约定：`knowledge/<category>/<slug>.md`，全部小写 kebab-case。一个主题一个页面，不要按对话建页。

常见分类（优先复用已有分类）：

```text
ai/llm             大模型、推理、训练
ai/ml              通用机器学习
frontend/ui        界面、交互、设计系统
frontend/react     React 生态
backend/api        接口、服务端
backend/db         数据库、存储
devops             部署、CI、可观测性
tools              工具、编辑器、工作流
```

标题用名词短语，例如 `Logits：模型的未归一化分数`，不要用“关于……的学习笔记”。

### 2. 写概述、核心机制和要点

笔记不是答案摘要。至少要让读者看懂：它解决什么问题，输入经过哪些步骤变成输出，哪些参数会改变结果，边界和失败模式是什么。

- `summary`：一句话定义，写清“是什么 + 作用”，不要空泛。
- `mechanism`：2–4 条，讲**运行机制**：调用链、数据流、状态变化、关键步骤，或参数如何影响结果。每条一句话，复杂机制最多两句。
- `points`：2–4 条，放公式、数量级、边界条件、失败模式、与相近概念的区别、工程取舍。
- 没有明显机制的纯事实/术语可以省略 `mechanism`，但 `points` 仍要写清关键约束，不能只重复“是什么”。
- 中文表述，保留英文术语（logits、softmax、token、temperature）。
- 数字、方向、因果关系必须准确；不确定就不写；不要用“可能/一般来说”凑内容。
- 不要把整段解释搬进去，不要写“本文介绍了……”。
- 已有页面只追加真正的新结论；重复的会被脚本自动跳过。

### 3. 调用 add 写入

```bash
python3 "$HOME/.config/opencode/skills/learn/scripts/learn.py" add <<'JSON'
{
  "category": "ai/llm",
  "slug": "logits",
  "title": "Logits：模型的未归一化分数",
  "summary": "大模型输出层为词表候选 token 生成的未归一化分数，经 softmax 变成采样概率。",
  "tags": ["llm", "inference", "softmax"],
  "categoryLabel": "大模型",
  "mechanism": [
    "模型最后一层为词表每个 token 输出一个 logit；logit 只保留相对大小，不是概率，可为负数。",
    "softmax 对 logits 取指数再除以总和，得到和为 1 的分布；所有 logit 同加一个常数不改变结果。",
    "temperature 在 softmax 前除以 logits：T<1 放大差异、分布更尖锐；T>1 压缩差异、分布更平坦。"
  ],
  "points": [
    "T→0 时最大 logit 的概率趋近 1，等价贪心解码；T→∞ 时趋近均匀采样。",
    "采样只改变概率，不改变 logit 的排序；logit 差值决定分布集中度。"
  ]
}
JSON
```

字段说明：

- `category`：`knowledge/` 下的目录，至少一层；脚本会创建缺失目录。
- `slug`：文件名（不含 `.md`），英文小写 kebab-case。
- `title`：页面标题，≤80 字；已存在页面时保留原标题。
- `summary`：一句话描述；新建页面时必填。
- `tags`：2–5 个英文小写标签。
- `categoryLabel`：目录的中文显示名，可省略；已有目录会沿用。
- `mechanism`：2–4 条运行机制（最多 8），每条 ≤400 字；没有明显机制时可省略。新建页面会生成 `## 核心机制`，已有页面会插到 `## 要点` 之前。
- `points`：2–4 条关键结论（最多 10），每条 ≤400 字。

输出是 JSON：

- `ok: true, changed: true`：已写入并提交；`pushed` 表示是否推送成功。
- `ok: true, changed: false`：机制和要点都已存在，没有产生提交。
- `ok: false`：看 `error`，修正后重试；不要盲目重复同一份内容。
- `pushError` 非空：提交已在本地，推送失败；告诉用户可执行 `/learn publish` 重试。
- `mechanismAdded` / `pointsAdded`：本次分别新增了多少条机制和要点。

默认 `add` 只提交到本地，不自动推送；用户可用 `/learn status` 审核，确认后 `/learn publish` 推送。

### 4. 需要改写或纠错时

如果新知识与旧页面矛盾，或你要重写整段而非追加：

1. 用文件工具读 `knowledge/...md`。
2. 直接改正文，保留 frontmatter 结构，但不要手动改 `updated`。
3. 运行：

```bash
python3 "$HOME/.config/opencode/skills/learn/scripts/learn.py" finalize knowledge/ai/llm/logits.md
```

`finalize` 会把 `updated` 更新为今天，并提交推送。

## 输出纪律

- 默认不要向用户解释“我写了哪些笔记”，也不要在回答末尾列归档清单。
- 只有以下情况说一句：写入失败、推送失败、用户询问。
- 普通用户回合最多调用一次 `add`；`/learn` 历史归档扫描例外，每个不同主题调用一次，最多 5 个页面。
- 不要把脚本输出原样贴给用户。

## 失败处理

- 提示“知识库目录不存在”：说明尚未安装或配置。让用户运行仓库里的 `integrations/opencode/install.sh`，不要擅自改仓库路径。
- 提示包含密钥：删除敏感内容后重试，不要绕过检查。
- 提示 git 失败：把关键错误告诉用户；不要执行 `git reset --hard`、`git push --force` 等破坏性操作。
- 网络导致推送失败：保留本地提交，提示 `/learn publish` 或稍后重试即可。

## 快速参考

```bash
LEARN="python3 $HOME/.config/opencode/skills/learn/scripts/learn.py"
$LEARN search "关键词"      # 搜索标题、标签、正文
$LEARN tree                 # 查看现有分类与页面
$LEARN status               # 待发布文件、改动行、未推送提交
$LEARN publish              # 提交并推送所有 pending 笔记
$LEARN finalize <path>      # 手动编辑后更新日期并提交
```

`status` 会列出相对 upstream 的所有待发布文件（含已提交未推送和未提交的改动），以及每个文件新增/删除的关键行和未推送提交，方便审核与补充。审核后可直接改笔记，再执行 `/learn publish`。
